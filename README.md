# WS OS

**Um portfólio profissional com a experiência de um sistema operacional.**

[![Acessar Portfólio](https://img.shields.io/badge/Acessar%20Portfólio-warlleys.dev-2563eb?style=for-the-badge)](https://warlleys.dev)
[![GitHub](https://img.shields.io/badge/GitHub-Repositório-181717?style=for-the-badge&logo=github)](https://github.com/warlleyz/ws-os)

O **WS OS** é um portfólio profissional interativo desenvolvido por **Warlley Silva**, estudante de Engenharia de Software com interesse em Desenvolvimento Full Stack.

O projeto apresenta uma abordagem diferente dos portfólios tradicionais: em vez de uma página convencional, o visitante interage com um ambiente inspirado em sistemas operacionais, explorando projetos, habilidades, formação acadêmica e informações profissionais através de aplicativos, janelas e funcionalidades integradas.

Desenvolvido com **React, JavaScript e Vite**, o sistema combina uma interface Desktop com uma experiência Mobile própria, utilizando uma arquitetura modular e integrações com serviços de backend.

## Visão geral

O WS OS foi criado para reunir informações profissionais, projetos e experiências de desenvolvimento em uma única plataforma.

A proposta é proporcionar uma navegação interativa, permitindo que cada visitante explore o conteúdo do portfólio no próprio ritmo, utilizando recursos familiares de sistemas operacionais.

O projeto contempla:

- Interface Desktop com janelas e barra de tarefas.
- Interface Mobile adaptada para dispositivos móveis.
- Aplicativos independentes e integrados ao sistema.
- Temas e opções de personalização visual.
- Widgets interativos.
- Assistente virtual integrado.
- Jogos e recursos interativos.
- Pesquisa global e navegação contextual.
- Suporte a Português e Inglês.
- Persistência local de preferências e arquivos.
- Integrações com serviços externos.
- Administração protegida de conteúdos e recursos.

## Funcionalidades

### Ambiente Desktop

O ambiente Desktop reproduz conceitos de sistemas operacionais tradicionais, com recursos de gerenciamento de aplicativos e organização do espaço de trabalho.

**Área de trabalho**

- Atalhos para aplicativos.
- Organização e posicionamento de ícones.
- Seleção de elementos.
- Menus de contexto.
- Wallpapers personalizáveis.
- Widgets opcionais.
- Persistência das preferências visuais.

**Gerenciamento de janelas**

- Abertura e fechamento de aplicativos.
- Movimentação e redimensionamento.
- Minimização, restauração e maximização.
- Organização e encaixe de janelas.
- Gerenciamento de foco.
- Suporte a múltiplas instâncias em aplicativos compatíveis.
- Integração com a barra de tarefas.

**Barra de tarefas**

- Acesso ao WS Menu.
- Gerenciamento dos aplicativos abertos.
- Pré-visualização de janelas.
- Central de notificações.
- Painel de controles rápidos.
- Acesso ao Wally.
- Informações de clima, data e horário.

**Navegação e interação**

- Pesquisa global.
- Atalhos de teclado.
- Menus contextuais.
- Notificações do sistema.
- Alternância entre aplicativos.
- Controles de aparência e personalização.

### Ambiente Mobile

O WS OS também possui uma interface específica para dispositivos móveis, preservando a identidade visual do projeto sem reproduzir integralmente o modelo de janelas do Desktop.

Entre seus recursos estão:

- Tela inicial adaptada.
- Navegação otimizada para toque.
- Aplicativos em tela cheia.
- Barra de navegação inferior.
- Acesso aos aplicativos compatíveis.
- Pesquisa e recursos do sistema.
- Preferências de interface independentes do Desktop.

### Personalização

O sistema permite ajustar diferentes aspectos da experiência visual:

- Temas claro e escuro.
- Cores de interface.
- Wallpapers.
- Transparência.
- Desfoque.
- Efeitos visuais.
- Cursores personalizados.
- Preferências de widgets.
- Idioma da interface.

As configurações compatíveis são armazenadas localmente, preservando as escolhas do visitante entre sessões.

## Wally — Assistente virtual

O **Wally** é o assistente integrado ao WS OS, desenvolvido para facilitar a exploração do portfólio.

Entre suas funcionalidades estão:

- Auxílio à navegação.
- Acesso contextual a aplicativos.
- Apresentação de informações sobre o portfólio.
- Respostas e orientações baseadas nos recursos locais disponíveis.
- Integração com a interface do sistema.

O Wally possui uma interface integrada ao ambiente e uma experiência estendida.

**Modo de funcionamento:** a versão publicada utiliza o Wally em modo local, sem chamadas a modelos de inteligência artificial remotos.

A arquitetura contempla a possibilidade de integração com serviços de IA, sujeita à configuração e disponibilidade do backend.

### Organização das responsabilidades

**Core:** concentra mecanismos fundamentais do sistema, como registro de aplicativos, gerenciamento de estado e integração entre funcionalidades.

**Apps:** contém as implementações dos aplicativos, mantendo suas responsabilidades organizadas.

**Features:** reúne funcionalidades reutilizáveis, como gerenciamento de janelas, notificações, widgets e painéis.

**Shells:** implementa as experiências Desktop e Mobile.

**Services:** centraliza integrações, comunicação com serviços externos e recursos de persistência.

**Shared:** contém componentes, contratos, utilitários e recursos compartilhados.

**Styles:** organiza estilos globais, tokens, temas e aspectos da personalização visual.

## Como executar

### Pré-requisitos

Para executar o projeto localmente, são necessários:

- **Node.js 24**
- **npm**
- **Git**

### 1. Clonar o repositório

```bash
git clone https://github.com/warlleyz/ws-os.git
cd ws-os
```

### 2. Instalar dependências

```bash
npm ci
```

Esse comando instala as dependências declaradas pelo projeto a partir do arquivo de lock.

### 3. Iniciar o ambiente de desenvolvimento

```bash
npm run dev
```

O Vite disponibilizará no terminal o endereço para acessar a aplicação localmente.

### 4. Gerar o build de produção

```bash
npm run build
```

Os arquivos gerados serão disponibilizados na pasta de saída configurada pelo Vite.

### 5. Pré-visualizar o build

```bash
npm run preview
```

**Observação:** o ambiente frontend pode ser executado independentemente, mas funcionalidades que dependem de APIs, autenticação, bancos de dados ou serviços externos exigem a configuração do backend e das respectivas variáveis de ambiente.

## Integrações e infraestrutura

O WS OS combina recursos executados diretamente no navegador com funcionalidades que dependem de infraestrutura externa.

### Recursos locais

Parte do funcionamento do sistema utiliza o armazenamento do navegador para manter:

- Preferências de aparência.
- Configurações de interface.
- Organização de elementos.
- Dados locais de aplicativos compatíveis.
- Arquivos criados ou armazenados pelo visitante.

### Serviços externos

Os serviços externos são utilizados conforme a necessidade de cada funcionalidade, incluindo:

- Operações administrativas.
- Persistência de conteúdos públicos.
- Interações com serviços protegidos.
- Dados de integrações.
- Recursos dependentes de APIs.

### Configuração de ambiente

As configurações de serviços externos devem ser realizadas através das variáveis de ambiente e dos mecanismos de configuração correspondentes.

Credenciais, tokens de acesso, senhas e segredos de infraestrutura não devem ser incluídos diretamente no código-fonte ou em commits.

O acesso a funcionalidades protegidas exige que o backend esteja configurado adequadamente.

## Segurança e privacidade

O projeto adota mecanismos de segurança compatíveis com suas funcionalidades, incluindo:

- Autenticação para recursos administrativos.
- Controle de autorização.
- Validação de entradas.
- Proteção de operações sensíveis.
- Limitação de requisições em serviços compatíveis.
- Integração com Cloudflare Turnstile.
- Separação entre recursos públicos e protegidos.
- Armazenamento local de preferências e arquivos do visitante.

O aplicativo Arquivos mantém os arquivos pessoais do visitante no ambiente local do navegador, enquanto os recursos públicos e administrativos podem utilizar serviços externos.

As medidas implementadas ajudam a reduzir riscos, mas não eliminam a necessidade de revisões, testes e atualizações de segurança.
